# 论文手工作流程

## 工具使用

### 一、docx skill - 生成Word格式论文

**模板格式必须先提取再生成**：

论文手生成 `.docx` 前，必须把用户模板或默认模板作为格式规范来源。默认模板位于：

`references/roles/论文手/references/论文模板.docx`

可使用以下脚本快速查看模板中的页面、段落、字体、字号、缩进、行距和表格格式：

```bash
python tools/docx/scripts/inspect_template_format.py references/roles/论文手/references/论文模板.docx
```

如需保存为 JSON：

```bash
python tools/docx/scripts/inspect_template_format.py references/roles/论文手/references/论文模板.docx -o template-format.json
```

#### 默认模板格式规范

根据当前默认 `论文模板.docx` 提取出的格式，生成论文时应遵守：

| 部分 | 字体与字号 | 段落格式 | 说明 |
|------|------------|----------|------|
| 页面 | A4：11906 × 16838 DXA | 上/下边距 1440 DXA，左/右边距 1800 DXA | 页眉 851 DXA，页脚 992 DXA |
| 正文 | 中文继承主题宋体，12pt（小四） | 首行缩进 2 字符，1.25 倍行距 | 模板中 `firstLineChars=200`，`line=300` |
| 论文题目 | 黑体，14pt | 居中，1.25 倍行距 | 不加粗 |
| “摘 要”标题 | 黑体，14pt | 居中，1.25 倍行距 | 字间保留空格 |
| 摘要正文 | 宋体，12pt | 首行缩进 2 字符，1.25 倍行距 | 按正文格式 |
| 关键词 | 宋体，12pt，加粗标签 | 不首行缩进，1.25 倍行距 | `关键词：`加粗，后接关键词 |
| 一级章节标题 | 宋体/主题中文字体，16pt，加粗 | 居中，1.25 倍行距 | 如“一、问题重述” |
| 二级标题 | 宋体，12pt，不加粗 | 左对齐，1.25 倍行距 | 如“1.1 问题背景”“7.1 模型的优点” |
| 三级标题（模型建立/求解） | 宋体，12pt，建议加粗 | 两端对齐，1.25 倍行距 | 模板局部存在不加粗样例，生成时统一加粗 |
| 正文 | 宋体，12pt | 首行缩进 2 字符，1.25 倍行距 | 模板部分占位正文未缩进/加粗，生成正式论文时不沿用该占位异常 |
| 符号说明表 | 表头 12pt 加粗 | 表格居中，内容居中 | 顶线、表头下横线、底线；无左右边框和内部竖线 |

> 注意：模板多数正文 run 没有显式写入“宋体”，而是通过 `minorEastAsia` 主题继承到宋体。用 `docx-js` 生成时应显式设置中文字体为 `SimSun` 或 `宋体`，避免不同环境主题解析不一致。

#### 三线表硬约束

论文中的符号说明、结果对比、参数表等学术表格必须使用三线表：

1. 表格只保留顶线、表头下横线、底线。
2. 禁止左右边框和内部竖线。
3. 普通数据行之间默认不加横线，除非用户模板或竞赛要求明确需要。
4. 表头使用 12pt、加粗、居中；表格整体居中。
5. 模板中的顶线/底线来自表格边框，表头下横线来自表头单元格 bottom border。
6. 使用 `docx-js` 时，必须同时设置 table border 和 cell border；仅设置 table border 容易在 Word/WPS 中渲染不一致。

#### 公式硬约束

论文中的数学公式必须是 Word 原生公式（OMML），不能只是 LaTeX 纯文本，也不能把截图当公式。

推荐流程：

1. 在正文生成阶段写占位符，如 `EQ_OBJECTIVE`、`EQ_CONSTRAINT_1`。
2. 使用 `tools/docx/scripts/equations.py replace` 将 LaTeX 公式替换为 OMML。
3. 替换后运行 `tools/docx/scripts/office/validate.py` 校验 `.docx`。
4. 如果使用 Markdown 全文转换方案，必须确认 `pandoc` 可用，并使用模板作为 reference doc。

公式脚本支持数学建模常用 LaTeX 子集：`\frac{}`、`\sqrt{}`、上下标、求和/积分符号、希腊字母、`\leq`、`\geq`、`\cdot`、`\times`、`\tag{}` 等。复杂公式如果超出子集，应拆分为多个简单公式或使用 pandoc 方案。

**使用方法**（基于模板创建新文档）：
```javascript
const { Document, Packer, Paragraph, TextRun, ImageRun, HeadingLevel } = require('docx');
const fs = require('fs');

const doc = new Document({
  styles: {
    default: { document: { run: { font: "SimSun", size: 24 } } },
    paragraphStyles: [
      { id: "Heading1", name: "Heading 1", basedOn: "Normal",
        run: { size: 32, bold: true, font: "SimHei" } },
    ]
  },
  sections: [{
    properties: {
      page: {
        size: { width: 11906, height: 16838 },
        margin: { top: 1440, right: 1800, bottom: 1440, left: 1800 }
      }
    },
    children: [
      new Paragraph({ heading: HeadingLevel.HEADING_1, children: [new TextRun("摘要")] }),
      // 更多内容...
    ]
  }]
});

Packer.toBuffer(doc).then(buffer => {
  fs.writeFileSync("论文.docx", buffer);
});
```

### 公式处理（重要）

`npm docx` 不支持数学公式。需要使用 **占位符 + 后处理** 或 **pandoc 方案** 将公式渲染为 Word 原生格式（OMML）。

**方案一：占位符替换（推荐用于复杂公式）**

在 docx-js 代码中，用占位符代替公式文本，生成 .docx 后再替换为 Word 公式：

```javascript
// 在 docx-js 中用占位符代替公式
new Paragraph({
  children: [
    new TextRun("模型的目标函数为："),
    new TextRun({ text: "EQ_LOSS", bold: true }),  // 占位符
    new TextRun("，约束条件为："),
    new TextRun({ text: "EQ_CONSTRAINT", bold: true }),  // 占位符
  ]
})
```

```bash
# 生成 .docx 后运行替换
python tools/docx/scripts/equations.py replace 论文.docx ^
    --replace "EQ_LOSS" "\\min L(\\theta) = \\frac{1}{n}\\sum_{i=1}^{n} (y_i - \\hat{y}_i)^2" ^
    --replace "EQ_CONSTRAINT" "\\sum_{j=1}^{m} a_{ij}x_j \\leq b_i" ^
    -o 论文_final.docx
```

**方案二：Markdown + pandoc（适合全篇写作）**

先用 Markdown 写论文（`$$...$$` 写公式），再转换为 .docx：

```bash
# 先将论文写成 paper.md
# 公式用标准的 LaTeX 语法

# 转换
python tools/docx/scripts/equations.py generate paper.md -o 论文.docx --template 模板.docx
```

Markdown 中的公式写法：
```markdown
## 4.1 数学模型

目标函数定义为：

$$
\min L(\theta) = \frac{1}{n}\sum_{i=1}^{n} (y_i - \hat{y}_i)^2 \tag{1}
$$

其中 $y_i$ 为真实值，$\hat{y}_i$ 为预测值。
```

### 三、paper_search skill - 搜索学术文献

```python
from openalex_scholar import OpenAlexScholar

scholar = OpenAlexScholar(email="your@email.com")

# 找经典文献：按引用量排序 + 领域过滤
papers = scholar.search_papers(
    query="linear programming optimization",
    sort="cited_by_count:desc",
    min_citations=10,
    year_from=2000,
    field_filter="mathematics",
    limit=15,
)

for paper in papers:
    print(f"引用格式: {paper.citation_format}")
    print(f"标题: {paper.title}")
    print(f"DOI: {paper.doi}")
```

## 工作流程

### 第一步：收集资料

| 资料类型 | 说明 |
|---------|------|
| 建模分析文档 | 理解建模手的分析和模型选择 |
| 代码和结果 | 查看编程手的代码实现和运行结果 |
| 题目文件 | 确认题目要求和背景 |
| 用户自定义模板 | 检查用户上传的论文模板和格式要求 |
| 前置合同 | 查看建模手的 Model Contract，获取论证框架 |

### 第二步：论证构建 (Argument Building)

**先构建论证，再写句子。** 一篇好论文不是章节的堆砌，而是一个完整的逻辑论证链。

#### 一句话论证模板

```
针对 [问题/系统]，我们采用 [方法/模型] 实现了 [进展/结果]，
通过 [证据] 支撑，适用范围为 [边界条件]。
```

**国赛示例**：
> 针对物流配送路径优化问题，本文采用改进遗传算法实现了配送距离缩短18.3%的效果，通过100次蒙特卡洛仿真验证，该算法在城市配送场景中效果显著。

**美赛示例**（English）：
> For the multi-echelon inventory optimization problem, we propose a hybrid GA-IP model that reduces total logistics cost by 22.4%, supported by sensitivity analysis across 5 demand scenarios, with reliable performance when demand volatility is below 30%.

#### 核心论证要素

| 要素 | 问题 | 示例 |
|------|------|------|
| **核心主张** | 这篇论文到底证明了什么？ | 本文模型在预测精度上优于所有基线 |
| **证据** | 用什么数据或结果支撑？ | RMSE降低15%，R²从0.82提升到0.91 |
| **边界** | 在什么条件下结论成立？ | 样本量>50时效果显著 |
| **意义** | 这项工作带来了什么？ | 为实时预测提供了可行的方案 |

#### Claim-Evidence 映射表

```markdown
| 主张 (Claim) | 证据 (Evidence) | 位置 | 状态 |
|-------------|----------------|------|------|
| 模型X准确率高 | 图3：对比柱状图，准确率95% | 第5章 | ✅ 已有证据 |
| 模型X稳定性好 | 表4：10次运行标准差<0.5 | 第6章 | ✅ 已有证据 |
| 模型X可推广到Y | 无数据支持 | 第8章 | ⚠️ 需补充说明 |
```

### 第三步：论文规划

1. **应用论证框架**: 将论证构建阶段的产出映射到各个章节
2. **确定使用格式**: 用户模板 / 默认格式
3. **确定章节**: 根据题目特点确定章节结构
4. **内容分配**: 核心章节占60%以上
5. **图表规划**: 匹配 Claim-Evidence 映射

### 缺失输入处理规则

撰写过程中常遇到信息不完整的情况，按以下规则处理：

| 场景 | 处理方式 |
|------|---------|
| 建模手没有给出模型公式 | 查阅 `assets/` 算法文档补充，标注来源 |
| 编程手没有生成某张图表 | 在论文中写 "图X展示了..." 但留占位符，标注缺失 |
| 某个结果的数值不明确 | 写 "结果表明..." 但留 `[待补充数据]` 占位符 |
| 文献引用信息不全 | 写 `[作者, 年份]` 占位符，标注待补充 |
| 某个结论缺乏证据支撑 | 弱化表述（"可能"、"初步表明"），在论文中说明局限性 |

**核心原则**（来自 nature-writing）：
- **不编造数据**：没有的数据就是没有，写占位符标记
- **不编造文献**：没有找到的引用就是不引用，不要猜测
- **暴露缺口**：如果核心证据缺失，在文中明确标出 `[待补充]`
- **优先问人**：占位符标记后，优先向建模手/编程手索要确切信息

**占位符格式规范**：
```markdown
[待补充：编程手需提供图3的数值结果]
[待补充：建模手需确认模型X的参数取值范围]
[待补充：此处的文献引用需要补充]
```

### 正式输出格式

每次论文撰写完成后，输出应包含以下五项内容：

```markdown
## 输出清单

### 1. 论文草稿 (Draft)
[论文.docx 文件]

### 2. 章节大纲 (Outline)
- 摘要：context→gap→approach→result→implication→boundary
- 引言：field scale→bottleneck→prior attempts→gap→present study
- 模型建立：选择→构建→求解
- 模型求解与结果：system→validation→main result→comparison→analysis
- 模型评价：advance→evidence→relation→constraints→future

### 3. 假设与缺失输入 (Assumptions & Missing)
- [假设1]：[具体说明]
- [缺失1]：[标记为待补充的内容]

### 4. Claim-Evidence 映射表
| 主张 | 证据 | 位置 | 状态 |
|-----|------|------|------|
| ... | ... | ... | 已支撑/待补充 |

### 5. 结构说明 (Why This Structure)
- 2-4 点说明为什么选择当前的章节组织方式
```

> **注意**：第3-5项不需要写入最终的论文.docx，而是作为论文手的交付说明附在项目文档中。

### 第五步：论文撰写

**撰写流程**：
```
0. 构建论证框架（一句话论证 + Claim-Evidence 映射）
   ↓
1. 使用 docx skill 读取论文模板
   ↓
2. 根据论证框架和模板创建论文框架
   ↓
3. 按章节填充内容：每段一个消息，Claims 紧挨 Evidence
   ↓
4. 插入编程手生成的图片
   ↓
5. 对每张图片进行详细的解释和分析
   ↓
6. 段落流检查：一段一消息，句间逻辑清晰
   ↓
7. 去AI味检查 + 格式规范检查 + 保存论文
```
