# 通用建模证据与验证契约

## 定位

本文件把历届优秀数学建模论文中反复出现的共同做法转化为可执行检查项。它不是固定模型清单，也不是要求每道题都使用同一套统计检验；应根据题目属于机理、预测、优化、仿真、评价、网络或混合问题选择适用项，并记录不适用的理由。

核心目标是让读者能沿着同一条链复核每个结论：

`题目机制与可得信息 → 假设和变量 → 数学模型 → 算法实现 → 诊断与验证 → 情景/决策结论 → 适用边界`

优秀论文的差异通常不在于模型名称更复杂，而在于这条链没有断点：模型和代码相符，结果有基线和诊断，方案在扰动下仍能解释，论文主张没有超过证据范围。

## 建模合同：M1 前置检查

在选定主模型前，为每个子问题建立一张模型合同，并把它写入 `题目分析报告.md`。至少包含以下字段：

| 字段 | 必须回答的问题 |
|---|---|
| 问题对象 | 研究对象、决策对象、响应变量和子问题输入输出是什么？ |
| 信息时点 | 每个变量在作出该决策时是否已经可得？预测题标出训练期/预测期，规划题标出决策前/决策后。 |
| 变量与单位 | 状态、决策、参数、潜变量、观测量的符号、类型、单位和量纲是什么？ |
| 假设与依据 | 哪些是假设成立模型才成立的关键条件？依据来自题目、领域知识、文献还是数据诊断？ |
| 目标与约束 | 目标函数、约束、边界、守恒关系、惩罚项和评价口径的精确定义是什么？ |
| 参数与数据 | 参数如何估计或校准，数据如何预处理，缺失/异常/抽样/聚合是否改变了研究对象？ |
| 代码映射 | 每个公式、约束和参数在代码中的函数、变量或配置位置是什么？代码是否实现了论文声称的模型？ |
| 输出与验证 | 输出如何回答题目，使用哪种正确性、拟合/预测、稳健性或领域合理性证据？ |
| 失败条件 | 数据范围、参数范围、可行域、样本量、算法收敛或外推边界在哪里？ |

以下情况在 M1 必须阻断并返工，而不是到论文阶段用文字掩盖：论文模型与代码模型不同；把估计后的经验修正说成模型内生项；约束只写在文字中却未实现；单位或时间方向冲突；使用决策时点之后才会产生的信息；输出无法对应题目要求。

## 模型选择与基线对照

每个子问题先明确一个合理的基线，再决定是否需要更复杂的主模型。基线可以是常数/历史均值、线性或简化机理模型、现行规则、贪心策略、无耦合版本或题目给出的经验方法。基线不是为了凑表，而是回答“复杂模型到底增加了什么”。

对照时必须保持可比：相同数据清洗、划分方式、评价指标、约束口径和随机种子；同时报告精度/目标值、稳定性、复杂度或运行成本。模型对比优先比较模型族，不把同一模型换一个参数或换一个初值包装成独立创新。若不存在合理基线，应说明原因，并用简化情形、理论边界、残差诊断或小规模精确解替代其可解释作用。

模型选择至少回答三件事：

1. 主模型利用了题目的哪一项结构或机制。
2. 相对于基线，提升是否超过随机波动、测量误差或实际决策所需的分辨率。
3. 复杂度、可解释性、数据需求和失败风险是否值得这项提升。

## 算法正确性与可行性：P1

把“程序运行成功”和“算法正确”分开检查。优化、仿真和统计学习至少按适用项提供以下证据：

- 优化：目标函数逐项核对，决策变量范围和硬约束真实生效；给出初始化、停止条件、容差、迭代或时间上限；有可行性检查，并在可能时与小规模穷举、线性规划、已知下界/上界或简单策略比较。
- 数值/物理：检查量纲、边界条件、守恒/单调性/对称性等可推断性质；改变步长、网格或容差后观察收敛；极端或退化输入不能静默产生 `NaN`、无穷值或不合物理的结果。
- 预测/统计/机器学习：训练、调参和评估严格分开；时间序列使用时间顺序或滚动回测，重复个体/组数据按组划分；检查特征是否包含目标发生后才知道的信息，并保留预处理参数的拟合范围。
- 随机算法：至少报告多初值或多种子下的分布、失败次数和运行成本，不只报告一次最优值；种子只用于复现，不得用挑选种子制造结论。
- 评价/决策：拆开指标标准化、权重、聚合和排序步骤；检查权重或效用的定义是否与题目方向一致，识别排序差异小于测量/估计误差的近似并列。

P1 结束时应能用真实数据或结构等价的小实例回答：代码读入了什么、求解了什么、满足哪些约束、返回了什么，以及这些输出为何是有限且有意义的。

## 分层验证与稳健性：P2

验证按结论类型分层，不以一个 $R^2$、一个最优值或一次运行代替全部验证：

| 层次 | 要证明的内容 | 适用证据示例 |
|---|---|---|
| 实现正确性 | 公式和代码没有明显逻辑/数值错误 | 小实例精确对照、边界 case、守恒/单调性、约束违约率 |
| 拟合或预测 | 对已观测或未见数据的解释能力 | 留出/交叉验证、滚动回测、RMSE/MAE/AUC、校准、残差和预测区间 |
| 优化或方案质量 | 方案确实优于基线且达到可接受质量 | 基线对照、下界/上界、可行率、最优性差距、多初值分布、运行成本 |
| 稳健性 | 关键输入、参数、权重或假设变化时结论是否保持 | 灵敏度、情景分析、消融、误差扰动、不同时间段/分组复验 |
| 领域合理性 | 结果符合题目机制和现实边界 | 单位/数量级、守恒、专家规则作为外部检查、已知事实或独立数据 |

每道题不必填满所有层次，但必须覆盖主张真正需要的层次，并解释省略项。对预测题，重点是信息泄漏、外推和不确定性；对优化题，重点是可行性、基线、近似质量和多次运行；对机理题，重点是边界、量纲、收敛和参数可辨识性；对评价/政策题，重点是权重与情景下的排序稳定性。

## 灵敏度、情景与近似最优

不要只给一个“最优方案”就结束。选择会影响结论的关键参数、权重、阈值、需求、成本或边界条件，扰动范围应由题目允许范围、测量误差、历史波动或文献依据确定。至少报告：

- 输出值或目标值的变化范围；
- 方案排名、分类、可行性或阈值是否改变；
- 结论稳定、条件稳定还是不稳定；
- 候选方案很接近时，是否应给出并列/备选方案和触发条件。

如果候选最优值之间的差异小于输入不确定性、重复运行波动或指标显示精度，不应把微小差异写成确定性的“显著优于”。论文应给出决策表：情景、推荐方案、关键数值、风险/代价、适用条件和必要的备用方案。

## 信息时序与数据泄漏审计

凡是预测、排班、控制、资源配置、预警或政策设计，都要给每个输入标注 `available_at`：它在决策前、决策时还是决策后才知道。禁止用事后测量、最终结果、未来窗口统计量或经过全数据拟合的变换参数作为事前特征，除非题目明确允许且论文说明这是事后分析而非可执行方案。

在代码和论文中分别记录：决策时点、特征截断时点、标签形成时点、训练/测试边界以及任何滚动聚合窗口。若一个变量既可作事前预测量又可作事后解释量，必须拆成两个明确版本，避免同名变量造成模型合同失真。

## 论文证据与主张强度

W1 建立内部主张—证据表。每条核心主张至少绑定一项可定位证据：公式/假设、代码输出、结果表、正式图、验证命令或已核验文献，并写出证据的限制。正式图不是数量配额，而是证明某一条主张；题注应说明数据范围、统计口径、区间或误差、基线和读者应观察的关系。

按证据强度选择措辞：

| 证据状态 | 可以说 | 不能越界说 |
|---|---|---|
| 仅样本内拟合/探索 | 在本数据与设定下呈现关联/趋势 | 普遍规律、因果关系、可直接部署 |
| 留出或滚动验证通过 | 对该验证范围具有预测/方案表现 | 对未覆盖群体或未来制度环境必然有效 |
| 多情景/多种子/扰动后保持 | 结论在给定扰动范围内稳定 | 对范围外参数不敏感 |
| 外部数据或独立事实核验 | 在已核验范围内具有外部一致性 | 已证明真实世界因果或长期效果 |
| 参数不可辨识、结果不稳定或证据缺失 | 作为探索性结果并列出限制 | 唯一最优、精确阈值、确定性建议 |

W2 必须清理“最优”“显著”“证明”“普适”“专家认为”等没有对应证据的强词，并在结论中保留适用数据范围、关键假设、最敏感因素和失败条件。

## 最低证据包

在交付每个子问题前，至少能定位以下内容；若某项不适用，写明理由和替代证据：

1. 一个完整模型合同，且论文公式、代码变量和结果口径一致。
2. 一个合理基线或简化/精确对照，以及统一指标下的比较。
3. 一项实现正确性或可行性检查。
4. 一项与结论类型匹配的泛化、领域合理性或方案质量验证。
5. 一项关键假设/参数/情景的稳定性分析，或明确说明无法开展及其影响。
6. 一条适用边界与限制，且限制来自实际数据、假设、算法或验证结果。

这组证据是质量底线，不规定必须使用某个具体模型、统计检验或图型。任何数量目标（图、表、公式）都不能替代上述证据。
